## Decisions Made
- CLAUDE.md structure: 1 root + 4 project-level files
- Memory structure: `state/` for hot state + permanent debt, `timeline/` for session logs
- Pre-Implementation Verification Gate: always run background verification agent before coding from specs
- Feature flag DACs split into Read/Write (codebase convention, not spec's unified IFeatureDac)
- UserFeatureOverride extends Entity (not AuditableEntity) — hard delete, thin audit only
- Cache invalidation methods on IFeatureGate interface (instance-local, not distributed)
- INVALID_CLIENT_ID as distinct reason code (not reusing CLIENT_NOT_SUBSCRIBED for Guid.Empty)
- No TrackedDacExecutor for feature flag DACs (ignoring Combo-Break for this feature)
- `"PortalDb"` pipeline key for all feature flag DACs (normalize mixed `"System"`/`"PortalDb"` usage later — tracked in state.md)
- `commandTimeout: SqlConstants.CommandTimeouts.TenantDb` on all feature flag DAC queries
- ILogger structured logging for FeatureGate decisions (not CheckpointTracker)
- CLIENT_OFF short-circuits without checking user overrides (truth table row 9: FORCE_ON cannot bypass CLIENT_OFF)
- FeatureGate in `Services/Features/` (not `Persistence/Services/` — it's business logic, not data access)
- CRITICAL #8: Full PUT with explicit values via UpdateFeatureAsync (not ToggleFeatureAsync)
- UpsertClientFeatureAsync takes explicit `bool isEnabled` (idempotent, not toggle)
- 204 No Content for all mutation endpoints (not 200)
- Feature/Client/User existence checks as guardrails in command handlers
- RBAC: 5 distinct permissions — ListView, GlobalEdit, ClientEdit, OverrideInsert, OverrideDelete
