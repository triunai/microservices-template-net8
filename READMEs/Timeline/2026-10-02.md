**First run: 33/35 passed (94%)**

2 failures — both FK violations on `client_features_client_id_fkey`. Root cause: `SeedTestClientAsync` generated client codes using `clientId.ToString()[..8]`, but UUIDv7 is time-ordered — two IDs generated in the same millisecond share the same first 8 hex chars. The `ON CONFLICT DO NOTHING` on the unique `code` index silently skipped the second INSERT, leaving the second client's `id` nonexistent.

**Fix**: Changed code generation to use `$"TC_{clientId:N}".ToUpper()[..20]` (N-format = no hyphens, 32 chars of entropy) and tightened conflict target to `ON CONFLICT (id) DO NOTHING`.

**Final: 106/106 all green (71 unit + 35 integration)**

### 2. Swarming Retrospective

**What worked:**
- Zero file conflicts — clean boundary (1 agent per output file)
- Speed — 7 min parallel vs ~14 min sequential
- Quality — 94% first-run pass rate

**What didn't:**
- Shared helpers (`SeedTestClientAsync`) written by agents independently — subtle UUIDv7 collision bug
- No incremental feedback during ~7 min agent execution
- ~60% prompt duplication (shared context repeated in both prompts)

**Lesson learned — optimal swarming pattern:**
1. **Step 0**: Build shared primitives (seed helpers, base classes, DTOs) — sequential
2. **Step 1**: Deploy parallel agents with file-level boundaries — each imports shared code
3. **Step 2**: Merge + verify (build, test, fix integration seams)

## Decisions Made
- Parallel subagent swarming: 2 agents max for this codebase (more would cause file conflicts)
- Shared primitives first, then parallel work — prevents helper code divergence
- UUIDv7 test data: use N-format GUID (32 chars) for uniqueness, not first-8-chars substring
- `ON CONFLICT (id) DO NOTHING` preferred over bare `ON CONFLICT DO NOTHING` in test helpers
